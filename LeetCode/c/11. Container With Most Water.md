# LeetCode 11. Container With Most Water - 完整學習筆記

## 📋 題目描述

給定一個長度為 `n` 的整數數組 `height`。有 `n` 條垂直線，第 `i` 條線的兩個端點是 `(i, 0)` 和 `(i, height[i])`。

找出其中的兩條線，使得它們與 x 軸共同構成的容器可以容納最多的水。

返回容器可以儲存的最大水量。

**說明**：你不能傾斜容器。

**範例**：
```
範例 1：
輸入：height = [1,8,6,2,5,4,8,3,7]
輸出：49
解釋：圖中垂直線代表輸入數組 [1,8,6,2,5,4,8,3,7]。
在此情況下，容器能夠容納水（表示為藍色部分）的最大值為 49。

範例 2：
輸入：height = [1,1]
輸出：1
```

**限制**：
- `n == height.length`
- `2 <= n <= 10⁵`
- `0 <= height[i] <= 10⁴`

**關鍵理解**：
```
容器的容量 = 寬度 × 高度

高度：兩條線中較短的那條
  min(height[left], height[right])

寬度：兩條線的距離
  right - left

範例：
  height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
           0  1  2  3  4  5  6  7  8
  
  選擇 index 1 和 8：
    高度 = min(8, 7) = 7
    寬度 = 8 - 1 = 7
    容量 = 7 × 7 = 49 ⭐

問題：
  如何快速找到最大容量？
```

## 💡 基礎知識：容器容量計算

### 容量公式

```
容量 = 寬度 × 高度

其中：
  寬度 = right - left
  高度 = min(height[left], height[right])

為什麼是 min？
  因為水會從較短的邊溢出
  
  範例：
    左邊高度 = 8
    右邊高度 = 3
    
    水只能到高度 3
    （否則會從右邊溢出）
    
    ┌────┐
    │    │         ┌──┐
    │    │    vs   │  │
    │    │         │  │
    │ 8  │         │3 │
    └────┘         └──┘
    
    容量取決於較短的邊 ⭐
```

## 🌟 你的解法：雙指針法（最優解）⭐⭐⭐⭐⭐

### 核心思想

```
雙指針策略：

初始：
  left = 0（最左邊）
  right = n-1（最右邊）
  → 寬度最大

移動規則：
  移動較短的那一邊 ⭐
  
  為什麼？
  - 寬度會減少
  - 只有移動較短邊，高度才可能增加
  - 移動較高邊，高度不可能增加

貪心策略：
  每次移動較短邊
  尋找可能更大的容量
```

### 你的代碼（完美！）⭐⭐⭐⭐⭐

```c
int maxArea(int* height, int heightSize) {
    int left = 0;
    int right = heightSize - 1;
    int max = 0;

    while (left < right) {
        // 計算高度（較短邊）
        int h = height[left] < height[right] ? 
                height[left] : height[right];

        // 計算面積
        int area = h * (right - left);
        
        // 更新最大值
        if (area > max)
            max = area;

        // 移動較短的邊 ⭐
        if (height[left] < height[right])
            left++;
        else
            right--;
    }

    return max;
}
```

## 💡 為什麼這個策略正確？

### 關鍵洞察 ⭐⭐⭐

```
問題：為什麼移動較短邊？

反證法：假設應該移動較高邊

當前狀態：
  height[left] < height[right]
  
  ┌────┐
  │    │           ┌──────┐
  │    │           │      │
  │left│           │right │
  └────┘           └──────┘
   短邊             長邊

如果移動長邊（right--）：
  新狀態：
    寬度：減少 ✗
    高度：最多 = height[left]（還是受短邊限制）
    
  結果：
    面積 = height[left] × (new_width)
         < height[left] × (old_width)
    
  面積一定變小 ✗

如果移動短邊（left++）：
  新狀態：
    寬度：減少 ✗
    高度：可能增加 ✓（如果新邊更高）
    
  結果：
    面積可能增加 ✓
    
結論：
  只有移動短邊，才有可能找到更大面積 ⭐
```

### 數學證明

```
設：
  left = i, right = j
  height[i] < height[j]（左邊是短邊）

當前面積：
  area(i, j) = height[i] × (j - i)

移動右邊（j--）：
  新面積 = min(height[i], height[j-1]) × (j-1-i)
         ≤ height[i] × (j-1-i)
         < height[i] × (j-i)
         = area(i, j)
  
  一定變小 ✗

移動左邊（i++）：
  新面積 = min(height[i+1], height[j]) × (j-i-1)
  
  如果 height[i+1] > height[i]：
    可能 > area(i, j) ✓
  
  有機會變大 ✓

結論：
  移動短邊是唯一有希望的策略 ⭐
```

## 💡 深入理解

### 雙指針的本質

```
雙指針法的核心思想：

搜索空間：
  所有可能的配對 (i, j)，i < j
  
  [0,1] [0,2] [0,3] ... [0,n-1]
        [1,2] [1,3] ... [1,n-1]
              [2,3] ... [2,n-1]
                    ...
                        [n-2,n-1]

雙指針策略：
  不需要嘗試所有配對
  通過貪心策略剪枝
  
  初始：[0, n-1]（寬度最大）
  每次：移動短邊（唯一有希望的方向）
  
  雖然只嘗試了 n 個配對
  但保證不會錯過最優解 ⭐
```

### 為什麼不會錯過最優解？

```
假設最優解是 (i*, j*)

情況 1：在雙指針路徑上
  會被遍歷到 ✓

情況 2：不在路徑上
  說明在到達 (i*, j*) 前
  某個維度被跳過了
  
  被跳過的原因：
    那一邊是短邊
    移動短邊是正確策略
    
  如果 height[i*] 或 height[j*] 是當時的短邊
  說明存在另一個更好的配對
  與 (i*, j*) 是最優解矛盾 ✗
  
結論：
  最優解一定會被遍歷到 ✓
```
