# LeetCode 876. Middle of the Linked List - 完整學習筆記

## 📋 題目描述

給定一個單鏈表的頭節點 `head`，返回鏈表的**中間節點**。

如果有**兩個中間節點**，則返回**第二個中間節點**。

**範例**：
```
範例 1：
輸入：head = [1,2,3,4,5]
輸出：[3,4,5]
解釋：鏈表的中間節點是節點 3

  1 → 2 → 3 → 4 → 5
          ↑
        中點

範例 2：
輸入：head = [1,2,3,4,5,6]
輸出：[4,5,6]
解釋：鏈表有兩個中間節點，值分別為 3 和 4，返回第二個

  1 → 2 → 3 → 4 → 5 → 6
              ↑
        第二個中點
```

**限制**：
- 鏈表的節點數範圍是 `[1, 100]`
- `1 <= Node.val <= 100`

**關鍵理解**：
```
奇數長度（5 個節點）：
  1 → 2 → 3 → 4 → 5
          ↑
      第 3 個（中點）
      
偶數長度（6 個節點）：
  1 → 2 → 3 → 4 → 5 → 6
              ↑
          第 4 個（第二個中點）
```

## 💡 基礎知識：鏈表中點

### 什麼是中點？

```
奇數長度：
  長度 = 5
  中點 = 第 ⌈5/2⌉ = 第 3 個節點
  
  索引：0  1  2  3  4
  節點：1→ 2→ 3→ 4→ 5
              ↑
           中點

偶數長度：
  長度 = 6
  中間有兩個：第 3 和第 4 個
  題目要求：返回第 4 個（第二個中點）
  
  索引：0  1  2  3  4  5
  節點：1→ 2→ 3→ 4→ 5→ 6
              ↑
        第二個中點
```

### 為什麼要找中點？

```
應用場景：
1. 歸併排序鏈表（148 題）
2. 判斷回文鏈表（234 題）
3. 重排鏈表（143 題）
4. 鏈表二分查找

找中點是很多鏈表算法的基礎
```

## 🔧 方法一：兩次遍歷

### 思路

先遍歷一次得到長度，再遍歷一次到中點。

### 代碼實現

```c
struct ListNode* middleNode(struct ListNode* head) {
    // 第一次遍歷：計算長度
    int length = 0;
    struct ListNode* curr = head;
    while (curr) {
        length++;
        curr = curr->next;
    }
    
    // 第二次遍歷：走到中點
    int mid = length / 2;  // 偶數時自動取較大的
    curr = head;
    for (int i = 0; i < mid; i++) {
        curr = curr->next;
    }
    
    return curr;
}
```

### 執行流程

```
範例：head = [1,2,3,4,5]

第一次遍歷：
  curr = 1 → 2 → 3 → 4 → 5 → NULL
  length = 5

計算中點位置：
  mid = 5 / 2 = 2（第 3 個節點，索引 2）

第二次遍歷：
  i = 0: curr = 1 → curr = 2
  i = 1: curr = 2 → curr = 3
  
  return 3 ✓
```

### 偶數長度處理

```
範例：head = [1,2,3,4,5,6]

length = 6
mid = 6 / 2 = 3（第 4 個節點，索引 3）

第二次遍歷：
  i = 0: curr = 2
  i = 1: curr = 3
  i = 2: curr = 4
  
  return 4 ✓（第二個中點）
```

### 複雜度分析

| 項目 | 複雜度 | 說明 |
|------|--------|------|
| **時間複雜度** | O(n) | 遍歷兩次 |
| **空間複雜度** | O(1) | 只用常數變量 |

### 優缺點

**優點**：
- ✅ 邏輯簡單直觀
- ✅ 容易理解

**缺點**：
- ❌ 需要遍歷兩次
- ❌ 不夠優雅

## 🌟 方法二：快慢指針（你的解法 - 最優解）

### 核心思想

```
Floyd's Algorithm 變體：

快指針 fast：每次走 2 步
慢指針 slow：每次走 1 步

當 fast 到達鏈表末尾時：
  slow 剛好在中點！

為什麼？
  fast 走的距離 = slow 的兩倍
  當 fast 到末尾時，slow 在中間
```

### 奇數和偶數長度的處理

```
奇數長度（n = 5）：
  初始：slow = 1, fast = 1
  
  迭代 1：slow = 2, fast = 3
  迭代 2：slow = 3, fast = 5
  迭代 3：fast->next = NULL，結束
  
  返回：slow = 3 ✓

  1 → 2 → 3 → 4 → 5 → NULL
  ●           ●
 slow        fast

偶數長度（n = 6）：
  初始：slow = 1, fast = 1
  
  迭代 1：slow = 2, fast = 3
  迭代 2：slow = 3, fast = 5
  迭代 3：slow = 4, fast = NULL，結束
  
  返回：slow = 4 ✓（第二個中點）

  1 → 2 → 3 → 4 → 5 → 6 → NULL
              ●           ●
             slow        fast
```

### 代碼實現（你的解法）

```c
struct ListNode* middleNode(struct ListNode* head) {
    struct ListNode* slow = head;
    struct ListNode* fast = head;
    
    while (fast && fast->next) {
        slow = slow->next;        // 走 1 步
        fast = fast->next->next;  // 走 2 步
    }
    
    return slow;  // slow 在中點
}
```

## 💡 快慢指針找中點的原理

### 數學證明

```
設鏈表長度為 n

slow 走的步數：k
fast 走的步數：2k

當 fast 到達末尾：
  - 奇數：fast 在最後一個節點
  - 偶數：fast 在 NULL

奇數情況（n = 5）：
  2k = n - 1
  k = (n-1)/2 = 2
  slow 在第 3 個節點（索引 2）✓

偶數情況（n = 6）：
  2k = n
  k = n/2 = 3
  slow 在第 4 個節點（索引 3）✓
  
結論：slow 總是在正確的中點位置
```

### 為什麼返回第二個中點？

```
偶數長度時有兩個中點：

  1 → 2 → 3 → 4 → 5 → 6
          ↑   ↑
        第1  第2

快慢指針的特性：
  當 fast 走到 NULL 時
  slow 走了 n/2 步
  剛好在第二個中點 ✓

如果要返回第一個中點：
  需要在 fast->next->next 到達 NULL 時停止
  （更複雜，通常不需要）
```
