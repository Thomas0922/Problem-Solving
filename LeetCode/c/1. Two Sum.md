# LeetCode 1. Two Sum - 完整學習筆記

## 📋 題目描述

給定一個整數陣列 `nums` 和一個目標值 `target`，請找出陣列中和為目標值的**兩個**數字的索引。

**限制條件**：
- 每個輸入只會有**唯一解**
- 不能使用同一個元素兩次
- 可以按任意順序返回答案

**範例**：
```
輸入：nums = [2, 7, 11, 15], target = 9
輸出：[0, 1]
解釋：nums[0] + nums[1] = 2 + 7 = 9

輸入：nums = [3, 2, 4], target = 6
輸出：[1, 2]

輸入：nums = [3, 3], target = 6
輸出：[0, 1]
```

---

## 💡 解題思路

### 核心概念：配對查找

```
目標：找到 nums[i] + nums[j] = target
變換：nums[j] = target - nums[i]

策略：
1. 對於每個 nums[i]，計算 complement = target - nums[i]
2. 查找 complement 是否已經出現過
3. 如果找到 → 返回兩個索引
4. 如果沒找到 → 記錄 nums[i]，繼續下一個
```

---

## 🔧 方法一：暴力解法（Brute Force）

### 思路
使用雙層迴圈，檢查每一對數字的和是否等於 target。

### 代碼實現

```c
/**
 * Note: The returned array must be malloced, assume caller calls free().
 */
int* twoSum(int* nums, int numsSize, int target, int* returnSize) {
    // 分配答案陣列
    int* ans = malloc(2 * sizeof(int));
    if (ans == NULL) {
        *returnSize = 0;
        return NULL;
    }
    
    // 雙層迴圈：檢查每一對
    for (int i = 0; i < numsSize; i++) {
        for (int j = i + 1; j < numsSize; j++) {
            if (nums[i] + nums[j] == target) {
                ans[0] = i;
                ans[1] = j;
                *returnSize = 2;
                return ans;
            }
        }
    }
    
    // 沒找到（題目保證有解，這裡不會執行到）
    free(ans);
    *returnSize = 0;
    return NULL;
}
```

### 複雜度分析

| 項目 | 複雜度 | 說明 |
|------|--------|------|
| **時間複雜度** | O(n²) | 外層迴圈 n 次，內層迴圈平均 n/2 次 |
| **空間複雜度** | O(1) | 只使用固定的額外空間（ans 陣列） |

### 執行流程範例

```
nums = [2, 7, 11, 15], target = 9

i=0, j=1: nums[0] + nums[1] = 2 + 7 = 9 ✓ 找到！返回 [0, 1]
```

### 優缺點

**優點**：
- ✅ 代碼簡潔，易於理解
- ✅ 不需要額外的資料結構
- ✅ 適合小型測資（n < 100）

**缺點**：
- ❌ 時間複雜度高（O(n²)）
- ❌ 大型測資會 TLE（Time Limit Exceeded）

## 🚀 方法二：Hash Table 解法（最佳解）

### 思路

使用 Hash Table 記錄已經遍歷過的數字，將查找時間從 O(n) 降到 O(1)。

**關鍵優化**：
- 不需要預先建立整個 Hash Table
- 邊查找邊插入（One-pass）
- 時間複雜度：O(n²) → O(n)

### 資料結構設計

```c
#define HASH_SIZE 10007  // 質數，減少碰撞

typedef struct {
    int value;  // 儲存數值（nums[i]）
    int key;    // 儲存索引（i）
    int used;   // 標記是否使用（0=空, 1=已用）
} HashTable;
```

**欄位說明**：
- `value`：儲存數值本身（用於匹配 complement）
- `key`：儲存該數值的索引（用於返回答案）
- `used`：區分「空位」和「有資料」

### 代碼實現

```c
#define HASH_SIZE 10007

typedef struct {
    int value;
    int key;
    int used;
} HashTable;

int* twoSum(int* nums, int numsSize, int target, int* returnSize) {
    // ═══════════════════════════════════════════════
    // 1️⃣ 記憶體分配與檢查
    // ═══════════════════════════════════════════════
    
    HashTable* hash = (HashTable*)calloc(HASH_SIZE, sizeof(HashTable));
    if (hash == NULL) {
        *returnSize = 0;
        return NULL;
    }

    int* ans = (int*)malloc(2 * sizeof(int));
    if (ans == NULL) {
        *returnSize = 0;
        free(hash);
        return NULL;
    }

    // ═══════════════════════════════════════════════
    // 2️⃣ 主要邏輯：遍歷 + 查找 + 插入
    // ═══════════════════════════════════════════════
    
    for (int i = 0; i < numsSize; i++) {
        // ─────────────────────────────────────────
        // 階段 A：查找配對數字
        // ─────────────────────────────────────────
        
        int com = target - nums[i];  // 計算 complement
        
        // 計算 complement 的 hash 位置
        int h = ((com % HASH_SIZE) + HASH_SIZE) % HASH_SIZE;
        int idx = h;
        
        // Linear Probing：查找 complement
        while (hash[idx].used) {
            if (hash[idx].value == com) {
                // ✅ 找到配對！
                ans[0] = hash[idx].key;  // 較早的索引
                ans[1] = i;               // 當前索引
                *returnSize = 2;
                free(hash);
                return ans;
            }
            idx = (idx + 1) % HASH_SIZE;  // 線性探測
        }
        
        // ─────────────────────────────────────────
        // 階段 B：插入當前數字
        // ─────────────────────────────────────────
        
        // 計算 nums[i] 的 hash 位置
        h = ((nums[i] % HASH_SIZE) + HASH_SIZE) % HASH_SIZE;
        idx = h;
        
        // Linear Probing：找空位
        while (hash[idx].used) {
            idx = (idx + 1) % HASH_SIZE;
        }
        
        // 插入資料
        hash[idx].value = nums[i];
        hash[idx].key = i;
        hash[idx].used = 1;
    }
    
    // ═══════════════════════════════════════════════
    // 3️⃣ 沒找到配對（題目保證有解，不會執行到）
    // ═══════════════════════════════════════════════
    
    *returnSize = 0;
    free(hash);
    free(ans);
    return NULL;
}
```

### 複雜度分析

| 項目 | 複雜度 | 說明 |
|------|--------|------|
| **時間複雜度** | O(n) | 單次遍歷，Hash 查找/插入平均 O(1) |
| **空間複雜度** | O(n) | Hash Table 最多儲存 n 個元素 |

**時間複雜度詳細分析**：
- 遍歷陣列：O(n)
- Hash 查找：平均 O(1)，最壞 O(n)
- Hash 插入：平均 O(1)，最壞 O(n)
- 總計：平均 O(n)，最壞 O(n²)（幾乎不會發生）

## 🎬 執行流程範例

```
nums = [2, 7, 11, 15], target = 9
HASH_SIZE = 10007

═══════════════════════════════════════════════════════════
i=0: nums[0] = 2
═══════════════════════════════════════════════════════════
階段 A：查找配對
  com = 9 - 2 = 7
  hash(7) = 7
  Hash[7].used = 0 → 沒找到 7

階段 B：插入當前數字
  hash(2) = 2
  Hash[2] = {value: 2, key: 0, used: 1}

Hash Table 狀態：
  [0]     [1]     [2]={2,0,1}     [3]     ...     [7]     ...
                       ↑插入

═══════════════════════════════════════════════════════════
i=1: nums[1] = 7
═══════════════════════════════════════════════════════════
階段 A：查找配對
  com = 9 - 7 = 2
  hash(2) = 2
  Hash[2].used = 1 → 檢查 Hash[2].value
  Hash[2].value = 2 = com ✓ 找到配對！
  
返回：
  ans[0] = Hash[2].key = 0
  ans[1] = 1
  return [0, 1] ✓
```

## 🔑 關鍵技術細節

### 1. Hash 函數設計

```c
int h = ((nums[i] % HASH_SIZE) + HASH_SIZE) % HASH_SIZE;
```

**為什麼需要兩次取模？**

| 步驟 | 操作 | 目的 |
|------|------|------|
| `nums[i] % HASH_SIZE` | 第一次取模 | 縮小範圍到 [-10006, 10006] |
| `+ HASH_SIZE` | 加上模數 | 將負數變正數 |
| `% HASH_SIZE` | 第二次取模 | 確保結果在 [0, 10006] |

**C 語言負數取模陷阱**：
```c
-15 % 10007 = -15  // ❌ C 語言保留符號
((-15 % 10007) + 10007) % 10007 = 9992  // ✅ 正確
```

### 2. Linear Probing（線性探測）

**碰撞處理策略**：
```c
while (hash[idx].used) {
    idx = (idx + 1) % HASH_SIZE;  // 往下一個位置找
}
```

**範例**：
```
hash(5) = hash(105) = 5  // 發生碰撞

插入順序：5, 105
Hash[5] = {value: 5,   key: 0, used: 1}
Hash[6] = {value: 105, key: 1, used: 1}  ← 碰撞後存這裡

查找 105：
  idx = 5 → value=5 ≠ 105 → idx=6
  idx = 6 → value=105 = 105 ✓ 找到！
```

### 3. 為什麼需要兩次 Hash 計算？

```c
for (int i = 0; i < numsSize; i++) {
    int com = target - nums[i];
    
    // 第一次：計算 complement 的 hash（查找）
    int h = hash_function(com);
    // ...查找 complement...
    
    // 第二次：計算 nums[i] 的 hash（插入）
    h = hash_function(nums[i]);
    // ...插入 nums[i]...
}
```

**原因**：`complement` 和 `nums[i]` 是不同的數值，它們的 hash 位置通常不同！

### 4. 為什麼用質數 10007？

**質數的優勢**：
- 減少 hash 碰撞（數學上的均勻分布特性）
- 10007 對於 LeetCode 測資（n ≤ 10⁴）夠用
- Load Factor ≈ 1.0（可接受範圍）

**Load Factor**：
```
Load Factor = n / HASH_SIZE
n = 10000, HASH_SIZE = 10007
Load Factor ≈ 0.999（接近滿載但可接受）
```

## ⚠️ 常見陷阱與注意事項

### 1. 記憶體管理

```c
// ✅ 正確：分配後立即檢查
HashTable* hash = calloc(HASH_SIZE, sizeof(HashTable));
if (hash == NULL) {
    return NULL;
}

// ✅ 正確：每個 return 前都要 free
if (找到配對) {
    free(hash);
    return ans;
}
```

### 2. `free(NULL)` 是安全的

```c
HashTable* hash = calloc(...);
if (hash == NULL) {
    free(hash);  // ✅ 安全！free(NULL) 什麼都不做
    return NULL;
}
```

### 3. 無限迴圈風險

```c
// ⚠️ 如果 Hash Table 滿了會無限循環
while (hash[idx].used) {
    idx = (idx + 1) % HASH_SIZE;
}

// ✅ 實務上不會發生（HASH_SIZE >> numsSize）
// 但生產環境建議加探測次數限制
```

### 4. 整數溢位

```c
int com = target - nums[i];
// ⚠️ 極端情況：target = INT_MAX, nums[i] = -1
//    com = INT_MAX - (-1) = 溢位！
// LeetCode 測資不會有這種情況，但寫產品代碼要注意
```

## 🏆 總結

**Two Sum 是 Hash Table 應用的經典題目**，核心概念是：

```
問題：查找速度慢（O(n)）
解決：Hash Table 加速查找（O(1)）
代價：額外空間（O(n)）
```

**關鍵記憶點**：
1. 配對查找 → complement = target - nums[i]
2. One-pass → 邊查找邊插入
3. 兩次 hash → 查找 complement、插入 nums[i]
4. Linear Probing → 處理碰撞
5. 負數取模 → `((x % n) + n) % n`
