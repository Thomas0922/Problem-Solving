# LeetCode 232. Implement Queue using Stacks - 完整學習筆記

## 📋 題目描述

請你僅使用兩個棧實現先進先出隊列。隊列應當支持一般隊列支持的所有操作（`push`、`pop`、`peek`、`empty`）。

實現 `MyQueue` 類：
- `void push(int x)` 將元素 x 推到隊列的末尾
- `int pop()` 從隊列的開頭移除並返回元素
- `int peek()` 返回隊列開頭的元素
- `boolean empty()` 如果隊列為空，返回 true；否則，返回 false

**說明**：
- 你**只能**使用標準的棧操作 —— 也就是只有 `push to top`、`peek/pop from top`、`size` 和 `is empty` 操作是合法的
- 你所使用的語言也許不支持棧。你可以使用 list 或者 deque（雙端隊列）來模擬一個棧，只要是標準的棧操作即可

**範例**：
```
輸入：
["MyQueue", "push", "push", "peek", "pop", "empty"]
[[], [1], [2], [], [], []]

輸出：
[null, null, null, 1, 1, false]

解釋：
MyQueue myQueue = new MyQueue();
myQueue.push(1); // queue is: [1]
myQueue.push(2); // queue is: [1, 2]
myQueue.peek();  // 返回 1
myQueue.pop();   // 返回 1, queue is: [2]
myQueue.empty(); // 返回 false
```

**限制**：
- `1 <= x <= 9`
- 最多調用 `100` 次 `push`、`pop`、`peek` 和 `empty`
- 假設所有操作都是有效的（例如，一個空的隊列不會調用 `pop` 或者 `peek` 操作）

**進階**：
你能否實現每個操作均攤時間複雜度為 O(1) 的隊列？換句話說，執行 n 個操作的總時間複雜度為 O(n)，即使其中一個操作可能花費較長時間。

**關鍵理解**：
```
棧：後進先出（LIFO）
  push(1), push(2), push(3)
  棧：[1, 2, 3]
       ↑
      top
  pop() → 3（後進先出）

隊列：先進先出（FIFO）
  push(1), push(2), push(3)
  隊列：[1, 2, 3]
        ↑     ↑
      front  rear
  pop() → 1（先進先出）

挑戰：
  如何用 LIFO 的棧
  實現 FIFO 的隊列？
```

## 💡 基礎知識：棧與隊列

### 棧 vs 隊列

```
棧（Stack）：
  特點：後進先出（LIFO）
  操作：
    push：從頂部加入
    pop：從頂部移除
  
  模型：一摞盤子
    最後放上去的
    最先被拿走
    
  範例：
    push(1) → [1]
    push(2) → [1,2]
    push(3) → [1,2,3]
    pop()   → 3，剩餘[1,2]

隊列（Queue）：
  特點：先進先出（FIFO）
  操作：
    push：從尾部加入
    pop：從頭部移除
  
  模型：排隊
    先來的人
    先被服務
    
  範例：
    push(1) → [1]
    push(2) → [1,2]
    push(3) → [1,2,3]
    pop()   → 1，剩餘[2,3]
```

### 為什麼需要兩個棧？

```
嘗試用一個棧：

push(1), push(2), push(3)
棧：[1, 2, 3]
     ↑
    top

想要 pop() 隊列的第一個元素（1）
但棧的 pop() 會返回 3 ✗

解決：
  需要把順序反轉
  [1, 2, 3] → [3, 2, 1]
  現在 pop() 返回 1 ✓

怎麼反轉？
  用另一個棧！⭐
  
  把第一個棧的元素
  一個個 pop 出來
  push 到第二個棧
  順序就反轉了！
```

## 🔧 方法：雙棧法（你的解法）⭐⭐⭐⭐⭐

### 核心思想

```
使用兩個棧：
  1. stackin（輸入棧）：負責 push
  2. stackout（輸出棧）：負責 pop/peek

push 操作：
  直接 push 到 stackin

pop/peek 操作：
  1. 如果 stackout 不為空
     直接從 stackout pop/peek
     
  2. 如果 stackout 為空
     把 stackin 的所有元素倒到 stackout
     然後從 stackout pop/peek

關鍵：懶惰轉移（Lazy Transfer）⭐
  只在 stackout 空時才轉移
  不是每次都轉移
```

### 你的代碼（完美！）⭐⭐⭐⭐⭐

```c
// ═══════════════════════════════════════
// 第一部分：實現棧
// ═══════════════════════════════════════
typedef struct Node {
    int val;
    struct Node* next;
} Node;

typedef struct stack {
    Node* top;
} stack;

stack* stackCreate(){
    stack* st = (stack*)malloc(sizeof(stack));
    st->top = NULL;
    return st;
}

void stackpush(stack* st, int x){
    Node* new = (Node*)malloc(sizeof(Node));
    new->val = x;
    new->next = st->top;
    st->top = new;
}

int stackpop(stack* st){
    if (st->top == NULL) return -1;
    Node* temp = st->top;
    int pop = temp->val;
    st->top = temp->next;
    free(temp);
    return pop;
}

int stackpeek(stack* st){
    if (st->top == NULL) return -1;
    return st->top->val;  
}

bool stackIsEmpty(stack* st) {
    return st->top == NULL;
}

void stackFree(stack* st) {
    while (!stackIsEmpty(st)) {
        stackpop(st);
    }
    free(st);
}

// ═══════════════════════════════════════
// 第二部分：用雙棧實現隊列
// ═══════════════════════════════════════
typedef struct {
    stack* stackin;   // 輸入棧
    stack* stackout;  // 輸出棧
} MyQueue;

MyQueue* myQueueCreate() {
    MyQueue* obj = (MyQueue*)malloc(sizeof(MyQueue));
    obj->stackin = stackCreate();
    obj->stackout = stackCreate();
    return obj;
}

// ═══════════════════════════════════════
// Push：O(1)
// ═══════════════════════════════════════
void myQueuePush(MyQueue* obj, int x) {
    // 直接推入 stackin
    stackpush(obj->stackin, x);
}

// ═══════════════════════════════════════
// 輔助函數：轉移元素 ⭐
// ═══════════════════════════════════════
void moveInputToOutput(MyQueue* obj) {
    // 只在 stackout 為空時轉移
    if (stackIsEmpty(obj->stackout)) {
        while (!stackIsEmpty(obj->stackin)) {
            int val = stackpop(obj->stackin);
            stackpush(obj->stackout, val);
        }
    }
}

// ═══════════════════════════════════════
// Pop：均攤 O(1)
// ═══════════════════════════════════════
int myQueuePop(MyQueue* obj) {
    moveInputToOutput(obj);
    return stackpop(obj->stackout);
}

// ═══════════════════════════════════════
// Peek：均攤 O(1)
// ═══════════════════════════════════════
int myQueuePeek(MyQueue* obj) {
    moveInputToOutput(obj);
    return stackpeek(obj->stackout);
}

// ═══════════════════════════════════════
// Empty：O(1)
// ═══════════════════════════════════════
bool myQueueEmpty(MyQueue* obj) {
    // 兩個棧都空才是空
    return stackIsEmpty(obj->stackin) && stackIsEmpty(obj->stackout);   
}

// ═══════════════════════════════════════
// Free：O(n)
// ═══════════════════════════════════════
void myQueueFree(MyQueue* obj) {
    stackFree(obj->stackin);
    stackFree(obj->stackout);
    free(obj);
}
```

```
初始狀態：

  stackin:  空
  stackout: 空

═══════════════════════════════════════
push(1)：

  stackpush(stackin, 1)
  
  stackin:  [1]
  stackout: 空

═══════════════════════════════════════
push(2)：

  stackpush(stackin, 2)
  
  stackin:  [2] → [1]  （2 在頂部）
            ↑
           top
  stackout: 空

═══════════════════════════════════════
peek()：

  1. moveInputToOutput()
     檢查：stackout 為空 ✓
     轉移：
       pop(stackin) → 2, push(stackout, 2)
       pop(stackin) → 1, push(stackout, 1)
  
  2. 轉移後：
     stackin:  空
     stackout: [1] → [2]  （1 在頂部）⭐
               ↑
              top
  
  3. stackpeek(stackout)
     返回：1 ✓（隊列的第一個元素）

═══════════════════════════════════════
pop()：

  1. moveInputToOutput()
     檢查：stackout 不為空 ✓
     跳過轉移（已經有了）⭐
  
  2. stackpop(stackout)
     返回：1 ✓
     
  3. 狀態：
     stackin:  空
     stackout: [2]

═══════════════════════════════════════
empty()：

  檢查：
    stackIsEmpty(stackin)  → true
    stackIsEmpty(stackout) → false
    
  返回：false ✓（還有元素 2）
```

### 為什麼這個方法巧妙？

```
關鍵：懶惰轉移（Lazy Transfer）⭐

不好的做法：
  每次 pop/peek 都轉移
  
  範例：
    push(1), push(2), push(3)
    pop() → 轉移 3 個元素
    pop() → 轉移 2 個元素
    pop() → 轉移 1 個元素
    
    效率低 ✗

你的做法（懶惰轉移）：
  只在 stackout 空時轉移
  
  範例：
    push(1), push(2), push(3)
    pop() → 轉移 3 個元素，返回 1
    pop() → 不轉移，直接返回 2 ⭐
    pop() → 不轉移，直接返回 3 ⭐
    
    每個元素只轉移一次 ✓

數學上：
  n 個操作
  每個元素最多轉移 1 次
  總轉移次數：O(n)
  均攤：O(1) ⭐
```

## 📊 複雜度分析

### 時間複雜度

| 操作 | 最壞情況 | 均攤複雜度 | 說明 |
|------|---------|-----------|------|
| **push** | O(1) | O(1) | 直接 push 到 stackin |
| **pop** | O(n) | O(1) ⭐ | 最壞需轉移 n 個元素 |
| **peek** | O(n) | O(1) ⭐ | 最壞需轉移 n 個元素 |
| **empty** | O(1) | O(1) | 檢查兩個棧 |

### 均攤分析（重要）⭐

```
為什麼 pop 是均攤 O(1)？

考慮 n 個操作：

最壞情況：
  push(1), push(2), ..., push(n)
  pop(), pop(), ..., pop()
  
第一次 pop：
  需要轉移 n 個元素
  時間：O(n)
  
後續 pop：
  直接從 stackout pop
  時間：O(1) 每次
  
總時間：
  轉移：O(n)
  n 次 pop：O(n)
  總共：O(2n) = O(n)
  
均攤每次操作：O(n) / n = O(1) ⭐

關鍵：
  每個元素最多被轉移 1 次
  push 到 stackin：1 次
  轉移到 stackout：1 次
  從 stackout pop：1 次
  
  每個元素總共 3 次操作
  均攤 O(1) ✓
```

### 空間複雜度

```
空間複雜度：O(n)

兩個棧總共存儲 n 個元素
```

### 方法二：push 時轉移（不推薦）

```c
// 每次 push 都轉移，保證 pop/peek O(1)

void myQueuePush(MyQueue* obj, int x) {
    // 1. 把 stackout 倒回 stackin
    while (!stackIsEmpty(obj->stackout)) {
        stackpush(obj->stackin, stackpop(obj->stackout));
    }
    
    // 2. push 新元素
    stackpush(obj->stackin, x);
    
    // 3. 把 stackin 倒到 stackout
    while (!stackIsEmpty(obj->stackin)) {
        stackpush(obj->stackout, stackpop(obj->stackin));
    }
}

int myQueuePop(MyQueue* obj) {
    return stackpop(obj->stackout);  // O(1)
}

// 時間複雜度：
// push: O(n) ✗
// pop: O(1) ✓

// 不推薦：push 是常用操作，不應該 O(n)
```

## ⚠️ 常見錯誤

### 錯誤 1：每次都轉移

```c
// ❌ 錯誤
void moveInputToOutput(MyQueue* obj) {
    // 總是轉移
    while (!stackIsEmpty(obj->stackin)) {
        stackpush(obj->stackout, stackpop(obj->stackin));
    }
}

// 問題：
// stackout 不為空時也轉移
// 會打亂順序 ✗

範例：
  stackin:  [3]
  stackout: [1] → [2]
  
  如果總是轉移：
  stackout: [1] → [2] → [3] ✗
  
  pop() 會返回 3 ✗（應該返回 1）

// ✓ 正確（你的做法）
if (stackIsEmpty(obj->stackout)) {  // 只在空時轉移
    // ...
}
```

### 錯誤 2：empty 判斷錯誤

```c
// ❌ 錯誤
bool myQueueEmpty(MyQueue* obj) {
    return stackIsEmpty(obj->stackout);  // 錯！
}

// 問題：
// stackin 可能還有元素

範例：
  stackin:  [1, 2]
  stackout: 空
  
  錯誤實現返回 true ✗
  實際隊列不為空

// ✓ 正確（你的做法）
return stackIsEmpty(obj->stackin) && stackIsEmpty(obj->stackout);
```

## 💡 雙棧法深入理解

### 為什麼需要兩個棧？

```
用一個棧的問題：

棧：[1, 2, 3]（3 在頂部）

想要 pop 隊列的第一個元素（1）
但 1 在棧底
無法直接訪問 ✗

解決方案 1：遍歷
  時間：O(n) ✗

解決方案 2：反轉順序
  把 [1, 2, 3] 反轉成 [3, 2, 1]
  現在 1 在頂部 ✓
  
如何反轉？
  用另一個棧！⭐
  
  原棧：[1, 2, 3]
       ↓ pop → push
  新棧：[3, 2, 1]（順序反轉）
  
這就是雙棧法的核心思想！
```

### 為什麼懶惰轉移有效？

```
關鍵觀察：

一旦元素到了 stackout
它們的相對順序就是正確的
不需要再轉移

範例：
  push(1), push(2), push(3)
  
  第一次 pop：
    轉移：stackout = [1, 2, 3]
    pop：1
    
  第二次 pop：
    stackout = [2, 3]
    直接 pop：2 ✓（不需要轉移）
    
  第三次 pop：
    stackout = [3]
    直接 pop：3 ✓（不需要轉移）

結論：
  每個元素最多轉移一次
  後續操作都是 O(1) ⭐
```

### 兩個棧同時有元素的情況

```
重要：兩個棧可以同時有元素 ⭐

範例：
  push(1), push(2), pop(), push(3)

執行過程：
  push(1), push(2)：
    stackin:  [2, 1]
    stackout: 空
    
  pop()（觸發轉移）：
    stackin:  空
    stackout: [1, 2]
    pop：1
    結果：
    stackin:  空
    stackout: [2]
    
  push(3)：
    stackin:  [3]  ⭐ stackin 又有元素了
    stackout: [2]  ⭐ stackout 也有元素
    
隊列邏輯：
  隊列 = stackout（從底到頂）+ stackin（從底到頂）
  
  範例中：
  stackout: [2]
  stackin:  [3]
  
  隊列 = [2, 3] ✓
  
下次 pop：
  stackout 不為空，pop(stackout) → 2
  
再次 pop：
  stackout 為空，轉移 stackin
  stackout: [3]
  pop(stackout) → 3
```
