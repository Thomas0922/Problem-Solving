# LeetCode 27. Remove Element - 完整學習筆記

## 📋 題目描述

給定一個整數陣列 `nums` 和一個值 `val`，**原地（in-place）**移除所有等於 `val` 的元素，並返回移除後陣列的新長度。

**要求**：
- 不能使用額外的陣列空間
- 必須原地修改輸入陣列
- 元素的順序**可以改變**
- 不需要考慮陣列中超出新長度後面的元素

**範例**：
```
輸入：nums = [3, 2, 2, 3], val = 3
輸出：2, nums = [2, 2, _, _]
解釋：移除所有 3，前 2 個元素是 [2, 2]

輸入：nums = [0, 1, 2, 2, 3, 0, 4, 2], val = 2
輸出：5, nums = [0, 1, 3, 0, 4, _, _, _]
解釋：移除所有 2，前 5 個元素是 [0, 1, 3, 0, 4]
```

**限制**：
- `0 <= nums.length <= 100`
- `0 <= nums[i] <= 50`
- `0 <= val <= 100`

---

## 💭 思路演進

### ❌ 初始想法：找到目標就移除

**直覺思路**：
```c
for (int i = 0; i < numsSize; i++) {
    if (nums[i] == val) {
        // 找到了！把它移除
        // 把後面的元素都往前移...
    }
}
```

**問題分析**：
1. **如何「移除」？** → 需要把後面所有元素往前挪
2. **留空問題**：
   ```
   [3, 2, 2, 3], val = 3
   
   移除 nums[0] = 3:
   [_, 2, 2, 3]  ← 前面留空了！
   
   需要把後面的往前移：
   [2, 2, 3, _]
   
   繼續移除 nums[2] = 3:
   [2, 2, _, _]  ← 又要移動！
   ```
3. **時間複雜度爆炸**：每次移除都要移動後面所有元素 → O(n²)

**核心問題**：
> 「移除」會在陣列中留下空位，需要不斷移動元素填補空缺

---

### ✅ 改進思路：反向思考 - 保留而非移除

**關鍵轉念**：
```
與其想「找到 val 就移除」
不如想「找到不是 val 的就保留」
```

**新策略**：
- 用雙指針技巧
- `j`：指向「保留區」的下一個位置
- `i`：遍歷整個陣列
- 遇到 `nums[i] != val` → 把它複製到 `nums[j]`，然後 `j++`
- 遇到 `nums[i] == val` → 跳過（自然被「覆蓋」掉）

**優勢**：
1. ✅ 不需要移動後面的元素
2. ✅ 不會留空（直接覆蓋）
3. ✅ 時間複雜度降到 O(n)

---

## 🎯 解題思路圖解

### 核心概念：雙指針覆蓋

```
概念：
- j 指針：「保留區」的末尾位置
- i 指針：遍歷整個陣列
- 遇到「非目標」元素 → 複製到保留區，j++
- 遇到「目標」元素 → 跳過（被後面的元素覆蓋）

結果：
[保留區：非 val 的元素][覆蓋區：被覆蓋的元素]
 ↑──────── j ────────↑
```

### 執行流程範例

```
nums = [3, 2, 2, 3], val = 3

初始狀態：
  j=0
  [3, 2, 2, 3]
   ↑
   j,i

───────────────────────────────────────
i=0: nums[0]=3
  nums[0]=3 == val → 跳過
  j 保持在 0
  
  [3, 2, 2, 3]
   ↑  ↑
   j  i

───────────────────────────────────────
i=1: nums[1]=2
  nums[1]=2 != val → 保留！
  nums[j] = nums[i] = 2
  j++ → j=1
  
  [2, 2, 2, 3]
      ↑     ↑
      j     i

───────────────────────────────────────
i=2: nums[2]=2
  nums[2]=2 != val → 保留！
  nums[j] = nums[i] = 2
  j++ → j=2
  
  [2, 2, 2, 3]
         ↑  ↑
         j  i

───────────────────────────────────────
i=3: nums[3]=3
  nums[3]=3 == val → 跳過
  j 保持在 2
  
  [2, 2, 2, 3]
         ↑     ↑
         j     i

───────────────────────────────────────
結束：return j = 2
結果：[2, 2, _, _]
       ↑──↑  (有效長度為 2)
```

## 🔧 代碼實現

### 最終解法

```c
int removeElement(int* nums, int numsSize, int val) {
    int j = 0;  // j 指向保留區的下一個位置
    
    // i 遍歷整個陣列
    for (int i = 0; i < numsSize; i++) {
        if (nums[i] != val) {      // 發現非目標元素
            nums[j] = nums[i];      // 複製到保留區
            j++;                     // 保留區擴大
        }
        // 如果 nums[i] == val，什麼都不做（跳過）
    }
    
    return j;  // j 就是保留區的長度
}
```

### 代碼邏輯拆解

```c
int removeElement(int* nums, int numsSize, int val) {
    // ═══════════════════════════════════════════════
    // 1️⃣ 初始化慢指針
    // ═══════════════════════════════════════════════
    int j = 0;  
    // j 的含義：
    // - 指向「保留區」的下一個可用位置
    // - 同時也代表「已保留元素的數量」
    
    // ═══════════════════════════════════════════════
    // 2️⃣ 快指針遍歷
    // ═══════════════════════════════════════════════
    for (int i = 0; i < numsSize; i++) {
        // i 的含義：
        // - 遍歷整個陣列
        // - 檢查每個元素是否需要保留
        
        // ───────────────────────────────────────
        // 判斷：是否保留當前元素
        // ───────────────────────────────────────
        if (nums[i] != val) {
            // ✅ 不是目標值 → 需要保留
            
            nums[j] = nums[i];  // 複製到保留區
            j++;                 // 保留區長度 +1
            
            // 注意：當 i == j 時，是自我賦值
            // 例如：[1, 2, 3], val=5
            //       每次都是 nums[0]=nums[0], nums[1]=nums[1]...
            //       雖然沒必要，但不影響正確性
        }
        // else {
        //     ❌ 是目標值 → 跳過（什麼都不做）
        //     這個元素會被後面的元素覆蓋
        // }
    }
    
    // ═══════════════════════════════════════════════
    // 3️⃣ 返回新長度
    // ═══════════════════════════════════════════════
    return j;
    // j 就是保留區的長度
    // 前 j 個元素是有效的（不含 val）
}
```

## 📊 複雜度分析

### 時間複雜度：O(n)

```c
for (int i = 0; i < numsSize; i++) {  // 循環 n 次
    if (nums[i] != val) {              // O(1) 判斷
        nums[j] = nums[i];              // O(1) 賦值
        j++;                             // O(1) 遞增
    }
}
```

**分析**：
- 單層迴圈：O(n)
- 每次操作：O(1)
- 總時間：O(n)

### 空間複雜度：O(1)

**分析**：
- 只使用了兩個額外變數：`i` 和 `j`
- 原地修改陣列，不使用額外空間
- 空間複雜度：O(1)

## 💡 關鍵技巧總結

### 1. 雙指針模式識別

當看到以下特徵時，考慮雙指針：
- ✅ **原地修改（in-place）**
- ✅ **移除/保留元素**
- ✅ **順序可以改變**（或已排序）
- ✅ **空間限制 O(1)**

### 2. 慢指針的含義

```c
int j = 0;  // j 有兩種理解方式：

// 理解 1：下一個可用位置
// j 指向「保留區」的下一個空位
// 新元素應該放在 nums[j]

// 理解 2：已保留元素數量
// j 同時代表已經保留了多少個元素
// 返回時 j 就是新長度
```

### 3. 覆蓋而非刪除

```
錯誤思維：「找到元素就刪除」
正確思維：「找到好元素就保留」

[3, 2, 2, 3], val=3
不是：刪除 3 → 移動元素
而是：保留 2 → 覆蓋 3
```

### 4. 自我賦值無妨

```c
if (nums[i] != val) {
    nums[j] = nums[i];  // 可能 i == j
    j++;
}

// 當沒有遇到 val 時：
// nums[0] = nums[0]  ← 自我賦值，但無害
// nums[1] = nums[1]
// ...
```

**為什麼不優化？**
- 加 `if (i != j)` 反而增加額外判斷
- 自我賦值的成本很低
- 代碼更簡潔

## 🔄 替代解法（供參考）

### 方法二：相向雙指針

```c
int removeElement(int* nums, int numsSize, int val) {
    int left = 0;
    int right = numsSize - 1;
    
    while (left <= right) {
        if (nums[left] == val) {
            // 發現目標值 → 用末尾元素替換
            nums[left] = nums[right];
            right--;
        } else {
            // 不是目標值 → 保留
            left++;
        }
    }
    
    return left;
}
```

**優點**：
- 減少賦值次數（只在遇到 val 時賦值）

**缺點**：
- 破壞相對順序（雖然題目允許）
- 代碼稍微複雜

**適用場景**：
- 如果 val 數量很多，可以減少操作
- 但實際性能差異不大

## 🏆 總結

**27. Remove Element 的核心思想**：

```
問題：如何高效移除元素？
轉念：不移除，而是保留好的元素去覆蓋壞的元素

工具：雙指針
- j：保留區的末尾
- i：遍歷指針

結果：O(n) 時間，O(1) 空間
```

**關鍵記憶點**：
1. 保留而非移除 → 避免元素移動
2. 快慢指針 → `j` 慢，`i` 快
3. `i` 從 0 開始 → 第一個元素也要檢查
4. 返回 `j` → 直接是長度
5. 覆蓋策略 → 簡單高效

- 同樣的雙指針框架
- 只改判斷條件和起始值
- 理解一題，掌握一類
