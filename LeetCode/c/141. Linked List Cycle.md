# LeetCode 141. Linked List Cycle - 完整學習筆記

## 📋 題目描述

給定一個鏈表的頭節點 `head`，判斷鏈表中是否有環。

如果鏈表中有某個節點，可以通過連續跟蹤 `next` 指針再次到達，則鏈表中存在環。為了表示給定鏈表中的環，評測系統內部使用整數 `pos` 來表示鏈表尾連接到鏈表中的位置（索引從 0 開始）。**注意：`pos` 不作為參數進行傳遞**。僅僅是為了標識鏈表的實際情況。

**如果鏈表中存在環**，則返回 `true`。否則，返回 `false`。

**範例**：
```
範例 1：
輸入：head = [3,2,0,-4], pos = 1
輸出：true
解釋：鏈表中有一個環，尾部連接到第二個節點

  3 → 2 → 0 → -4
      ↑_________|

範例 2：
輸入：head = [1,2], pos = 0
輸出：true
解釋：鏈表中有一個環，尾部連接到第一個節點

  1 → 2
  ↑___|

範例 3：
輸入：head = [1], pos = -1
輸出：false
解釋：鏈表中沒有環

  1 → NULL
```

**限制**：
- 鏈表中節點的數目範圍是 `[0, 10^4]`
- `-10^5 <= Node.val <= 10^5`
- `pos` 為 `-1` 或者鏈表中的一個**有效索引**

**進階要求**：
你能用 **O(1)** 空間解決此題嗎？

---

## 💡 基礎知識：什麼是環？

### 環的定義

```
無環鏈表：
  1 → 2 → 3 → 4 → NULL
  
有環鏈表：
  1 → 2 → 3 → 4
      ↑_________|
      
  從節點 4 的 next 指向節點 2
  形成環：2 → 3 → 4 → 2 → 3 → 4 → ...
```

### 環的特點

```
1. 無限循環：
   - 遍歷永遠不會到達 NULL
   - 會無限重複訪問相同的節點

2. 檢測方法：
   - 記錄訪問過的節點（哈希表）
   - 快慢指針（Floyd's Algorithm）⭐

3. 環的起點：
   - pos 表示環的起點位置
   - pos = -1 表示無環
```

## 🔧 方法一：哈希表

### 思路

用哈希表記錄訪問過的節點，如果再次訪問到已記錄的節點，說明有環。

### 代碼實現（C++ 版本）

```cpp
bool hasCycle(ListNode *head) {
    unordered_set<ListNode*> visited;
    
    ListNode* curr = head;
    while (curr) {
        if (visited.count(curr)) {
            return true;  // 再次訪問到已記錄的節點
        }
        visited.insert(curr);
        curr = curr->next;
    }
    
    return false;  // 到達 NULL，無環
}
```

### 執行流程

```
範例：head = [3,2,0,-4], pos = 1

  3 → 2 → 0 → -4
      ↑_________|

步驟 1：訪問節點 3
  visited = {3}
  curr = 2

步驟 2：訪問節點 2
  visited = {3, 2}
  curr = 0

步驟 3：訪問節點 0
  visited = {3, 2, 0}
  curr = -4

步驟 4：訪問節點 -4
  visited = {3, 2, 0, -4}
  curr = 2

步驟 5：再次訪問節點 2
  2 在 visited 中 ✓
  return true
```

### 複雜度分析

| 項目 | 複雜度 | 說明 |
|------|--------|------|
| **時間複雜度** | O(n) | 最多訪問每個節點一次 |
| **空間複雜度** | O(n) | 哈希表存儲 n 個節點 ❌ |

### 優缺點

**優點**：
- ✅ 邏輯簡單直觀
- ✅ 容易理解和實現

**缺點**：
- ❌ 需要 O(n) 額外空間
- ❌ 不符合進階要求

## 🌟 方法二：快慢指針（Floyd's Cycle Detection - 你的解法）

### 核心思想

```
Floyd's Cycle Detection Algorithm
（弗洛伊德環檢測算法 / 龜兔賽跑算法）

關鍵洞察：
  如果有環，快指針最終會追上慢指針！
  
比喻：
  在操場跑步（環形跑道）
  - 慢跑者：每次跑 1 米
  - 快跑者：每次跑 2 米
  
  如果是環形跑道，快跑者最終會「套圈」追上慢跑者
  如果是直線跑道，快跑者會先到終點
```

### 為什麼快慢指針一定會相遇？

#### 數學證明

```
假設：
  - 環的長度為 C
  - 慢指針在環中的位置為 S
  - 快指針在環中的位置為 F
  
設快慢指針的距離差為 D = F - S

每次迭代：
  - 慢指針移動 1 步
  - 快指針移動 2 步
  - 距離差減少 1

因為是環：
  - 距離差最多為 C
  - 每次減少 1
  - 最多 C 次迭代後，距離差變為 0
  
結論：快指針必定會追上慢指針！
```

#### 直觀理解

```
想像環形跑道：

起點：slow 和 fast 都在起點
  ●___________
  |           |
  |___________|
  
迭代 1：
  slow 走 1 步，fast 走 2 步
  ●____●______
  |           |
  |___________|
  
迭代 2：
  slow 走 1 步，fast 走 2 步
  ___●___●____
  |           |
  |___________|
  
...

某次迭代：fast 追上 slow
  _____●______
  |           |
  |___________|
  
  slow 和 fast 在同一位置 ✓
```

### 代碼實現（你的解法）

```c
bool hasCycle(struct ListNode *head) {
    struct ListNode* slow = head;
    struct ListNode* fast = head;
    
    while (fast && fast->next) {
        slow = slow->next;        // 慢指針走 1 步
        fast = fast->next->next;  // 快指針走 2 步
        
        if (slow == fast) {
            return true;  // 相遇，有環
        }
    }
    
    return false;  // fast 到達 NULL，無環
}
```

### 執行流程

```
範例：head = [3,2,0,-4], pos = 1

  3 → 2 → 0 → -4
      ↑_________|

初始：
  slow = 3
  fast = 3

迭代 1：
  slow = slow->next = 2
  fast = fast->next->next = 0
  slow != fast ✗

迭代 2：
  slow = slow->next = 0
  fast = fast->next->next = 2
  slow != fast ✗

迭代 3：
  slow = slow->next = -4
  fast = fast->next->next = -4
  slow == fast ✓
  
  return true
```

### 詳細追蹤（圖解）

```
  3 → 2 → 0 → -4
      ↑_________|

初始狀態：
  slow: 3
  fast: 3
  
  3 → 2 → 0 → -4
  ●           
  slow, fast
      ↑_________|

迭代 1：slow 走 1 步，fast 走 2 步
  slow: 2
  fast: 0
  
  3 → 2 → 0 → -4
      ●   ●
     slow fast
      ↑_________|

迭代 2：slow 走 1 步，fast 走 2 步
  slow: 0
  fast: 2（從 -4 繞回來）
  
  3 → 2 → 0 → -4
      ●   ●
     fast slow
      ↑_________|

迭代 3：slow 走 1 步，fast 走 2 步
  slow: -4
  fast: -4（從 2 → 0 → -4）
  
  3 → 2 → 0 → -4
              ●
          slow, fast
      ↑_________|

相遇！return true
```

### 無環情況

```
範例：head = [1,2,3]

  1 → 2 → 3 → NULL

初始：
  slow = 1
  fast = 1

迭代 1：
  slow = 2
  fast = 3

迭代 2：
  fast->next = NULL
  跳出循環
  
  return false
```

| **空間複雜度** | O(1) | 只用兩個指針 ✓ |

### 優勢

**你的解法的優點**：
- ✅ **空間 O(1)**：符合進階要求 ⭐

## 💡 快慢指針技巧深入理解

### 循環條件的重要性

```c
// ✓ 正確（你的做法）
while (fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
    if (slow == fast) return true;
}

為什麼這樣寫？
  1. fast != NULL：確保 fast 有效
  2. fast->next != NULL：確保 fast->next->next 不會空指針
  
  如果只寫 while (fast)：
    fast = fast->next->next 可能會空指針崩潰 ❌
```

### 先移動後判斷 vs 先判斷後移動

```c
// ✓ 正確（你的做法）
while (fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
    if (slow == fast) return true;  // 移動後判斷
}

// ❌ 錯誤
while (fast && fast->next) {
    if (slow == fast) return true;  // 先判斷
    slow = slow->next;
    fast = fast->next->next;
}

問題：
  初始時 slow = fast = head
  如果先判斷，會誤認為有環！
  
解決：
  先移動，再判斷（你的做法）✓
```

### 為什麼是走 2 步而不是 3 步？

```
快指針每次走 k 步：

k = 2：
  - 必定相遇 ✓
  - 最優效率
  
k = 3：
  - 可能「跳過」慢指針，錯過相遇
  - 某些環可能無法檢測 ❌
  
k = 4, 5, ...：
  - 同樣問題，可能跳過
  
結論：k = 2 是最優選擇
```

```c
// 問題：

    slow = slow->next;
```

```c
// ❌ 錯誤

    if (slow == fast) return true;  // 先判斷

// 初始時 slow == fast == head
```

### 142. Linked List Cycle II（找環的起點）

```c
// 142 題：找出環的起點位置

struct ListNode *detectCycle(struct ListNode *head) {
    struct ListNode *slow = head, *fast = head;
    
    // 步驟 1：檢測是否有環（141 題）
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        
        if (slow == fast) {
            // 有環，進入步驟 2
            
            // 步驟 2：找環的起點
            slow = head;  // 重置 slow 到起點
            while (slow != fast) {
                slow = slow->next;
                fast = fast->next;  // fast 也走 1 步
            }
            return slow;  // 環的起點
        }
    }
    
    return NULL;  // 無環
}

// 數學證明：
// 設：
//   a = 起點到環入口的距離
//   b = 環入口到相遇點的距離
//   c = 相遇點到環入口的距離
//   
// 相遇時：
//   slow 走了：a + b
//   fast 走了：a + b + c + b = a + 2b + c
//   
// fast 是 slow 的兩倍：
//   2(a + b) = a + 2b + c
//   2a + 2b = a + 2b + c
//   a = c
//   
// 結論：
//   從起點走 a 步 = 從相遇點走 c 步
//   會在環入口相遇！
```

### 進階思考

#### 問題 1：為什麼時間複雜度是 O(n)？

```
情況 1：無環
  - fast 走到 NULL
  - 最多走 n 步
  - O(n)

情況 2：有環
  - 設非環部分長度為 a
  - 環的長度為 c
  
  slow 進入環時：
    - slow 在環入口
    - fast 在環中某處（最多領先 c 步）
  
  每次迭代：
    - 距離差減少 1
    - 最多 c 次迭代相遇
  
  總時間：a + c = O(n)

結論：O(n)
```

#### 問題 2：能否用更少的空間？

```
已經是 O(1) 空間了！

其他方法：
1. 破壞鏈表結構（不推薦）
   - 反轉鏈表方向
   - 檢測是否回到起點
   
2. 修改節點值（不推薦）
   - 標記訪問過的節點
   - 需要恢復原值

快慢指針已經是最優方案
```

#### 問題 3：如果不能修改鏈表怎麼辦？

```
快慢指針本來就不修改鏈表！

只是移動指針，不修改：
- 節點的 val
- 節點的 next
- 鏈表結構

所以快慢指針適用於只讀鏈表 ✓
```

### 快慢指針模板

```c
// 通用模板
struct ListNode* slow = head;
struct ListNode* fast = head;

while (fast && fast->next) {
    slow = slow->next;        // 慢指針走 1 步
    fast = fast->next->next;  // 快指針走 2 步
    
    // 根據題目需求處理
    if (slow == fast) {
        // 相遇處理
    }
}

// 循環結束後
// slow 在某個特殊位置（如中點）
```

### 應用場景

```
1. 檢測環：
   - 如果有環，必定相遇
   - 141 題

2. 找中點：
   - fast 到尾時，slow 在中點
   - 876 題

3. 找環起點：
   - 相遇後，重置一個指針
   - 142 題

4. 判斷回文：
   - 找中點，反轉後半部分
   - 234 題
```

### 關鍵要點

```

   slow = head
   fast = head

2. 循環條件：
   while (fast && fast->next)

   slow = slow->next

4. 先移動後判斷：
   避免初始誤判
```

## 🏆 總結

**141. Linked List Cycle 的核心**：

```
問題：判斷鏈表是否有環
關鍵：Floyd's Cycle Detection（快慢指針）

最優解法（你的解法）：
struct ListNode* slow = head;
struct ListNode* fast = head;

while (fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
    
    if (slow == fast) {
        return true;
    }
}

return false;

時間複雜度：O(n)
空間複雜度：O(1) ✓
```

3. ✅ **先移動後判斷**：避免初始誤判
4. ✅ **相遇即有環**：快指針會追上慢指針
5. ✅ **到達 NULL 即無環**：fast 到達終點
