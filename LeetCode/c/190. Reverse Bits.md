# LeetCode 190. Reverse Bits - 完整學習筆記

## 📋 題目描述

將給定的 32 位無符號整數的二進制位反轉。

**注意**：
- 輸入是一個長度為 32 的二進制字符串表示的無符號整數
- 在某些語言（如 Java）中，沒有無符號整數類型。在這種情況下，輸入和輸出都將被指定為有符號整數類型，並且不應影響你的實現

**範例**：
```
輸入：n = 00000010100101000001111010011100
輸出：964176192 (00111001011110000010100101000000)
解釋：
輸入的二進制串 00000010100101000001111010011100 反轉後為
             00111001011110000010100101000000，即十進制的 964176192

輸入：n = 11111111111111111111111111111101
輸出：3221225471 (10111111111111111111111111111111)
解釋：
輸入的二進制串 11111111111111111111111111111101 反轉後為
             10111111111111111111111111111111，即十進制的 3221225471
```

**限制**：
- 輸入是一個長度為 32 的二進制字符串

**進階**：如果多次調用這個函數，你將如何優化你的算法？

## 💡 核心概念

### 什麼是位反轉？

```
原始：  10110010  (從左到右：第 0-7 位)
反轉：  01001101  (第 0 位變第 7 位，第 1 位變第 6 位...)

規則：
第 i 位 → 第 (31-i) 位
```

### 視覺化理解

```
32 位整數反轉：

原始：[b31][b30][b29]...[b2][b1][b0]
       ↓    ↓    ↓        ↓   ↓   ↓
反轉：[b0][b1][b2]...[b29][b30][b31]
```

## 🔧 方法一：逐位處理（基礎解法）

### 思路

從右到左逐個取出 n 的位，從左到右放入 result：

```
1. 取出 n 的最低位（n & 1）
2. 將這位放入 result 的最低位
3. result 左移一位（為下一位騰空間）
4. n 右移一位（處理下一位）
5. 重複 32 次
```

### 代碼實現（標準寫法）

```c
uint32_t reverseBits(uint32_t n) {
    uint32_t result = 0;
    
    for (int i = 0; i < 32; i++) {
        result <<= 1;        // result 左移一位
        result |= (n & 1);   // 取出 n 的最低位，放入 result
        n >>= 1;             // n 右移一位
    }
    
    return result;
}
```

### 代碼實現（你的寫法）

```c
uint32_t reverseBits(uint32_t n) {
    uint32_t result = 0;
    
    for (int i = 0; i < 32; i++) {
        result = (n & 1) | (result << 1);  // 等價於上面的寫法
        n >>= 1;
    }
    
    return result;
}
```

**兩種寫法的差異**：
- 標準寫法：先左移 result，再加入新位
- 你的寫法：同時左移和加入新位
- **邏輯完全等價**，因為 `|` 運算符可交換

### 執行流程

#### 範例：n = 13 (00001101)

```
初始：
  n      = 00001101
  result = 00000000

───────────────────────────────────────
迭代 1 (i=0)：
  n & 1 = 1
  result <<= 1 → result = 00000000
  result |= 1  → result = 00000001
  n >>= 1      → n = 00000110
  
───────────────────────────────────────
迭代 2 (i=1)：
  n & 1 = 0
  result <<= 1 → result = 00000010
  result |= 0  → result = 00000010
  n >>= 1      → n = 00000011
  
───────────────────────────────────────
迭代 3 (i=2)：
  n & 1 = 1
  result <<= 1 → result = 00000100
  result |= 1  → result = 00000101
  n >>= 1      → n = 00000001
  
───────────────────────────────────────
迭代 4 (i=3)：
  n & 1 = 1
  result <<= 1 → result = 00001010
  result |= 1  → result = 00001011
  n >>= 1      → n = 00000000
  
───────────────────────────────────────
迭代 5-32：
  n & 1 = 0（n 已經是 0）
  result 不斷左移，右邊補 0
  
───────────────────────────────────────
最終結果：
  result = 10110000000000000000000000000000
         = 2952790016
```

### 詳細圖解

```
n = 00001101 (只看 8 位示意)

步驟 1：取出 1，result = 00000001
        n = 00000110

步驟 2：取出 0，result = 00000010
        n = 00000011

步驟 3：取出 1，result = 00000101
        n = 00000001

步驟 4：取出 1，result = 00001011
        n = 00000000

步驟 5-8：取出 0，result 繼續左移
         result = 10110000

對比：
  原始：00001101
  反轉：10110000 ✓
```

### 複雜度分析

| 項目 | 複雜度 | 說明 |
|------|--------|------|
| **時間複雜度** | O(1) | 固定循環 32 次 |
| **空間複雜度** | O(1) | 只用常數空間 |

### 優缺點

**優點**：
- ✅ 邏輯清晰，易於理解
- ✅ 代碼簡潔
- ✅ 不需要額外空間

**缺點**：
- ⚠️ 需要循環 32 次（無法避免）
- ⚠️ 如果多次調用，沒有優化空間

## 🚀 方法二：分治法（Divide and Conquer）

### 核心思想

不是逐位處理，而是：
1. 先交換左右 16 位
2. 再在每 16 位內交換左右 8 位
3. 再在每 8 位內交換左右 4 位
4. ...以此類推

**類比**：
```
反轉字符串 "ABCD"：
方法 1（逐字符）：取 D→C→B→A，一個個放
方法 2（分治）：
  - 先交換 "AB" 和 "CD" → "CDAB"
  - 再在 "CD" 內交換 → "DCAB"
  - 再在 "AB" 內交換 → "DCBA" ✓
```

### 代碼實現

```c
uint32_t reverseBits(uint32_t n) {
    // 步驟 1：交換左右 16 位
    n = (n >> 16) | (n << 16);
    
    // 步驟 2：在每 16 位內，交換左右 8 位
    n = ((n & 0xff00ff00) >> 8) | ((n & 0x00ff00ff) << 8);
    
    // 步驟 3：在每 8 位內，交換左右 4 位
    n = ((n & 0xf0f0f0f0) >> 4) | ((n & 0x0f0f0f0f) << 4);
    
    // 步驟 4：在每 4 位內，交換左右 2 位
    n = ((n & 0xcccccccc) >> 2) | ((n & 0x33333333) << 2);
    
    // 步驟 5：在每 2 位內，交換左右 1 位
    n = ((n & 0xaaaaaaaa) >> 1) | ((n & 0x55555555) << 1);
    
    return n;
}
```

### 詳細推導

#### 步驟 1：交換左右 16 位

```
原始：[高 16 位][低 16 位]
      AAAAAAAAAAAAAAAA BBBBBBBBBBBBBBBB

n >> 16：00000000000000000 AAAAAAAAAAAAAAAA
n << 16：BBBBBBBBBBBBBBBB 00000000000000000

結果：BBBBBBBBBBBBBBBB AAAAAAAAAAAAAAAA
```

#### 步驟 2：交換每 16 位內的左右 8 位

```
掩碼解釋：
0xff00ff00 = 11111111000000001111111100000000
0x00ff00ff = 00000000111111110000000011111111

當前：BBBBBBBBBBBBBBBB AAAAAAAAAAAAAAAA
     [B1][B2][B3][B4] [A1][A2][A3][A4]

(n & 0xff00ff00) >> 8：提取 [B1] 和 [A1]，右移
(n & 0x00ff00ff) << 8：提取 [B2] 和 [A2]，左移

結果：[B2][B1][B4][B3] [A2][A1][A4][A3]
```

#### 步驟 3-5：類似邏輯

```
步驟 3：交換每 8 位內的左右 4 位
  掩碼：0xf0f0f0f0, 0x0f0f0f0f

步驟 4：交換每 4 位內的左右 2 位
  掩碼：0xcccccccc, 0x33333333

步驟 5：交換每 2 位內的左右 1 位
  掩碼：0xaaaaaaaa, 0x55555555
```

### 掩碼含義表

| 步驟 | 掩碼 1 | 掩碼 2 | 二進制模式 |
|------|--------|--------|-----------|
| 2 | 0xff00ff00 | 0x00ff00ff | 11110000... |
| 3 | 0xf0f0f0f0 | 0x0f0f0f0f | 11110000... |
| 4 | 0xcccccccc | 0x33333333 | 11001100... |
| 5 | 0xaaaaaaaa | 0x55555555 | 10101010... |

### 執行範例

```
n = 00000010100101000001111010011100

步驟 1：交換左右 16 位
  → 00011110100111000000001010010100

步驟 2：交換每 16 位內的左右 8 位
  → 10011100000111100010010000000010

步驟 3：交換每 8 位內的左右 4 位
  → 01001110000001111000001000100000

步驟 4：交換每 4 位內的左右 2 位
  → 00110110000000111010000010001000

步驟 5：交換每 2 位內的左右 1 位
  → 00111001011110000010100101000000 ✓
```

### 複雜度分析

| 項目 | 複雜度 | 說明 |
|------|--------|------|
| **時間複雜度** | O(1) | 固定 5 步操作 |
| **空間複雜度** | O(1) | 只用常數空間 |

### 優缺點

**優點**：
- ✅ 只需 5 步操作（vs 32 次循環）
- ✅ 沒有循環，效率更高
- ✅ 常數時間複雜度

**缺點**：
- ❌ 代碼不直觀，難以理解

## 🌟 方法三：查表法（空間換時間）

### 思路

預先計算所有 8 位數字（0-255）的反轉結果，然後分 4 次查表。

### 代碼實現

```c
// 預計算的反轉表
uint8_t reverseTable[256];

// 初始化查表（只需執行一次）
void buildReverseTable() {
    for (int i = 0; i < 256; i++) {
        uint8_t rev = 0;
        uint8_t num = i;
        for (int j = 0; j < 8; j++) {
            rev = (rev << 1) | (num & 1);
            num >>= 1;
        }
        reverseTable[i] = rev;
    }
}

// 使用查表反轉 32 位
uint32_t reverseBits(uint32_t n) {
    return (reverseTable[n & 0xff] << 24) |
           (reverseTable[(n >> 8) & 0xff] << 16) |
           (reverseTable[(n >> 16) & 0xff] << 8) |
           (reverseTable[(n >> 24) & 0xff]);
}
```

### 工作原理

```
將 32 位分成 4 個字節：

原始：[Byte3][Byte2][Byte1][Byte0]

反轉：[Rev(Byte0)][Rev(Byte1)][Rev(Byte2)][Rev(Byte3)]

查表：
  reverseTable[Byte0] → 放在最高字節
  reverseTable[Byte1] → 放在次高字節
  reverseTable[Byte2] → 放在次低字節
  reverseTable[Byte3] → 放在最低字節
```

### 範例

```
n = 0x12345678

Byte0 = 0x78 → reverseTable[0x78] = 0x1E → 放在 bits 24-31
Byte1 = 0x56 → reverseTable[0x56] = 0x6A → 放在 bits 16-23
Byte2 = 0x34 → reverseTable[0x34] = 0x2C → 放在 bits 8-15
Byte3 = 0x12 → reverseTable[0x12] = 0x48 → 放在 bits 0-7

結果：0x1E6A2C48
```

### 複雜度分析

| 項目 | 複雜度 | 說明 |
|------|--------|------|
| **時間複雜度** | O(1) | 固定 4 次查表 |
| **空間複雜度** | O(256) | 需要 256 字節的查表 |
| **初始化時間** | O(256) | 只需執行一次 |

### 適用場景

**優點**：
- ✅ 如果多次調用，非常高效
- ✅ 固定 4 次查表，速度極快

**缺點**：
- ❌ 需要額外空間（256 字節）
- ❌ 需要初始化
- ❌ 單次調用反而更慢（因為要初始化）

**建議**：
- 題目問「進階：如果多次調用這個函數，你將如何優化？」
- 這就是答案！ ⭐

## 🎯 代碼風格對比

### 你的寫法 vs 標準寫法

```c
// 你的寫法
result = (n & 1) | (result << 1);

// 標準寫法
result <<= 1;
result |= (n & 1);

// 或者合併成一行
result = (result << 1) | (n & 1);
```

**分析**：
- 你的寫法：`(n & 1) | (result << 1)` ✓
- 標準寫法：`(result << 1) | (n & 1)` ✓
- **邏輯完全等價**（因為 `|` 可交換）

**差異**：
```
你的寫法強調：「取出新位 + 左移舊結果」
標準寫法強調：「左移舊結果 + 加入新位」

後者更符合「構建」的思維：
1. 先為新位騰空間（左移）
2. 再把新位放進去（或運算）
```

**建議**：
- 兩種都正確
- 建議用標準寫法（更常見）
- 但你的寫法也完全 OK

## ⚠️ 常見錯誤

### 錯誤 1：循環次數錯誤

```c
// ❌ 錯誤：循環到 n == 0 為止
while (n) {
    result = (result << 1) | (n & 1);
    n >>= 1;
}
// 問題：如果原始數字後面有 0，會丟失

// 例如：n = 8 (1000)
// 循環 4 次就停止了，丟失了後面的 28 個 0

// ✅ 正確：必須循環 32 次
for (int i = 0; i < 32; i++) {
    result = (result << 1) | (n & 1);
    n >>= 1;
}
```

### 錯誤 2：忘記左移

```c
// ❌ 錯誤：忘記左移 result
for (int i = 0; i < 32; i++) {
    result |= (n & 1);  // 缺少 result <<= 1
    n >>= 1;
}
// 問題：所有位都堆在最低位

// ✅ 正確
for (int i = 0; i < 32; i++) {
    result <<= 1;       // 必須左移
    result |= (n & 1);
    n >>= 1;
}
```

### 錯誤 3：返回類型錯誤

```c
// ❌ 錯誤：返回 int 而不是 uint32_t
int reverseBits(int n) {
    // ... 可能導致符號問題
}

// ✅ 正確：使用無符號整數
uint32_t reverseBits(uint32_t n) {
    // ...
}
```

## 🏆 總結

**190. Reverse Bits 的核心**：

```
問題：反轉 32 位整數的二進制
策略：逐位取出，反向放入

基本解法（推薦）：
for (int i = 0; i < 32; i++) {
    result = (result << 1) | (n & 1);
    n >>= 1;
}

時間複雜度：O(1) - 固定 32 次循環
空間複雜度：O(1)
```

**關鍵記憶點**：
1. 必須循環 32 次（不能到 n==0 就停）
2. `result << 1` 為新位騰空間
3. `n & 1` 取出最低位
4. `n >>= 1` 處理下一位
5. 多次調用場景可用查表法優化


**關聯題目**：191. Number of 1 Bits, 231. Power of Two
